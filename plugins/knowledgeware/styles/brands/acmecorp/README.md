# acmecorp — AcmeCorp (fictional)

Grounded, technical, quietly confident: a warm paper canvas, deep teal as the single working accent, rust for contrast moments. AcmeCorp is a fictional brand that ships with the plugin for two reasons: it shows what a brand folder looks like, and it is the folder to copy when you add a brand of your own.

| File | What it is |
|---|---|
| `brand.md` | The brandbook: prose rules for every consumer, with a YAML precision layer loaders read first (spec: `skills/brandware/references/brandbook-spec.md`) |
| `tokens.json` | Derived cache, regenerated by `scripts/load-style.js` when `brand.md` changes; never edit it |
| `assets/logo-light.svg`, `assets/logo-dark.svg` | The logo for light and dark backgrounds; slideware's HTML decks put it in the running footer |
| `README.md` | This file: what the brand is, where it came from, how to use it |

**Use it.** Name the brand in a request to any knowledgeware skill: "build the deck in the acmecorp brand", "an acmecorp knowledgebase site".

**Copy it for a new brand.** Copy this folder to `$KNOWLEDGEWARE_BRANDS_DIR/<name>/` (or `styles/brands/<name>/`), then rewrite `brand.md` for the brand, replace the logos in `assets/` (keep the file names, so decks find them), delete `tokens.json` (the loader rebuilds it), and fill in the provenance below. The brandware skill's §Add / import walks through it.

## Provenance

- **Source:** fictional; written for the knowledgeware plugin as its example brand.
- **Version / date:** see the plugin's CHANGELOG.
- **Owner:** the plugin maintainers.

For a real brand, record where the brandbook came from (a design kit, a brand site, a PDF guide), its version or date, and who owns it, so the next person can tell whether this copy is current.
