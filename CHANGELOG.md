# Changelog

Notable changes to the marketplace and its plugins. Each plugin carries its own version in [`marketplace.json`](./.claude-plugin/marketplace.json); a marketplace release (tagged `vX.Y.Z`, matching the catalog version) groups the plugin versions that shipped together. Claude Code updates an installed plugin when its version changes, so every shipped change to a plugin bumps its version.

## [1.2.1] — unreleased

### Release branches for the directory

- Submitted plugins track `release/<plugin>` in Anthropic's directory instead of `main`, so day-to-day merges don't start a scan. `scripts/cut-release.sh <plugin>` fast-forwards that branch to `origin/main` after checking the plugin's version went up, prints the changelog lines and files since the last cut, and asks before pushing. `release/knowledgeware` starts at the 1.9.3 state.

### Directory listing fields, every plugin

- Each plugin's `plugin.json` now carries the fields Anthropic's directory reads for a listing: `icon` (the `icon.png` beside the manifest), `documentationUrl` (the plugin's README), `supportUrl` (this repository's issues), `privacyPolicyUrl` (the new [PRIVACY.md](./PRIVACY.md)) and `termsOfServiceUrl` (the MIT license). The catalog can't hold them directly, since `claude plugin validate` warns on each in a marketplace entry, so they live under the entry's free-form `metadata.directory` and the generator hoists them into `plugin.json`. No plugin version changes for this: Claude Code ignores the fields, so there is nothing for an installed copy to pick up.
- [PRIVACY.md](./PRIVACY.md) states what the plugins collect (nothing), what leaves the machine and to whom (the model providers you already use, plus knowledgeware's and research-team's documented fetches), and where output stays.

### knowledgeware 1.12.6

- **Builds in any order, and on more layouts.** `steps` on an html slide now also takes an array with one entry per click: item indices, or the `id` of an element anywhere in the slide's HTML (a group in an inline SVG, a `<span id>` in a body string), grouped in an array when several arrive together, so `[[0, 1], 2]` shows two bullets at once and the third next, and a chart in a two-column body builds group by group. `true` and `"rest"` work on `two-column` (left, then right), `image-caption` (image, then caption) and `quote` (quote, then attribution) as well as `bullets` and `card-row`. Items that share a click stagger among themselves; an index past the slide's items is a build error, an id no element has is a note. Inside the builder, renderers only mark items `data-step` and one pass turns the marks into fragments, so a new layout joins builds with one helper call. The theme sets `will-change: auto` on fragments inside an SVG, which Chrome otherwise clips after a viewBox change. Docs note that a `?presenter` window previews builds without a second window. From the Enterprise Enablement deck, where 26 of 50 slides use it.

### knowledgeware 1.12.5

- **Builds, PowerPoint-style.** `bullets` and `card-row` slides take `steps: true` (every item on its own click) or `steps: "rest"` (the first shows at once); each item becomes a Reveal fragment whose entrance motion now plays on its click instead of while it's still hidden (two theme rules, which hand-written fragments with `data-a` get too). Builds play only while a presenter window is connected (`S` or `P`); a deck read on its own, or in review mode, shows every slide complete. Speaker notes mark the clicks as `[click n]`; the guideline for notes is one sentence for the slide, a line per build, one thing to remember, and no slide longer than 5 to 10 minutes.
- **A planning convention for decks that need one.** `deck-plan.md` beside the deck's source, in tables rather than prose: sources named once with short references cited as `D<deck>.S<slide>`, the owner's dated decisions, one table per section with each slide's key, source, builds and status, and free-form "Not taken" and "Mechanics" notes. A template ships with the html format; the build reads the file when present and reports, for information, rows marked done whose key isn't in the deck and slides the plan doesn't mention. The maintenance spec names it as a deck's planning record (rung 3), separate from a spec. Proposed from the Enterprise Enablement rebuild.

### knowledgeware 1.12.4

- **A clean deck to share, a review deck to build with.** `index.html` (and `index-<lane>.html`) no longer carry review mode at all; a deck with `review: true` (or `--review`) also writes `index.review.html` and `index-<lane>.review.html`, which inline `review.js` and whose lane switcher stays among the review files. A deck that drops review mode loses its stale `.review` files at the next build. Share the plain files; keep the `.review` files with the deck folder.
- **The review deck saves itself.** Connect the deck folder once (Chrome's folder picker, from the review bar; the handle is remembered, one "Allow" click per browser session) and `edits.json` is written after every change, `Save` becomes `Save now`, and the page reloads on the same slide when a rebuild lands, so "Claude, rebuild the deck" is the whole loop with no server. The autosave never writes over a newer build (it reloads instead) and keeps another build's leftovers for Claude beside the page's own edits. `serve-deck.js` and `Shift+B` stay as the one-key alternative; without either, the confirm bar says what to do.
- **Slides have layout knobs, blocks have addresses, and both fold.** A slide may set `ratio` ("40/60", two columns), `gap`, `pad` and `scale` (the image's width in percent), which the builder renders as custom properties the layout CSS reads; structural blocks (columns, cards, bullets, the image, the quote, the big number's figure) carry `data-b` with a kind in `data-bk`, and a slide's `tweaks` (`{ "cards.1": { dx, dy } }`, `w` on media) land on them as `--dx` / `--dy` / `--w`. The fold learns to set or remove a knob, replace `tweaks`, and remove or reorder the items of `cards` and `items` (new fields go last; a moved item keeps the comment above it); in a lane, knobs and tweaks go to the overlay and array edits are layered. These are the fields review mode's layout mode writes.
- **Layout mode and a text formatter in review mode.** `L` switches review mode between text and layout. In layout mode the blocks the builder marks get dotted outlines by kind (blocks in muted ink, card and bullet items in the success tone, media in the second accent; text fields keep the accent); a click selects; dragging nudges a block or an image and reorders a card or bullet among its siblings; arrows nudge the selection (Shift ×10); Del removes a card or bullet; a corner handle resizes an image and the bar between two columns sets their ratio; the panel holds the slide's knobs (gap, padding, columns, image) with a reset each, and the selection's nudge. Everything applies to the deck as you do it and is recorded against the built value as the slide's `knobs`, `tweaks` and `arrays`, folded at the next build. Over a focused light-HTML field a small bar offers bold, italic, code, link, clear, a colour from the brand's roles and a size step; Cmd+B, Cmd+I and Cmd+K work too. Titles and kickers stay plain, since the builder escapes them.
- **Structural edits apply to the live deck at once.** Hiding, deleting or reordering slides in the overview now changes the deck you're looking at (sections re-appended in the pending order, hidden and deleted ones detached, Reveal re-synced on the same slide), with the running footer's page counters renumbered, so the deck and the overview agree before the rebuild writes it into `slides.js`. Discard puts the built order back. The presenter window keeps the built order until the rebuild.
- **Review mode toggles from the overview too:** `e` works there, and an Edit / Done button sits beside Rebuild deck.
- **Hotkeys are shown in capitals** everywhere the deck names one (`E`, `Shift+B`, `H · Del · Shift+←→`), replacing 1.12.3's lowercase convention.
- **Hidden slides are unmistakable in the overview:** an ink-tinted overlay (it dims a light slide and lifts a dark one) with a centred "Hidden" pill, instead of a faint wash and an icon the slide's own content could hide.

### knowledgeware 1.12.3

- **The deck re-fits above the notes drawer.** With `N` open, the deck gives up the drawer's height (a `--rp-reserve-bottom` property on `<html>`, kept current as the notes change length per slide) and Reveal rescales the slide into the space above it, so long notes never cover the slide. Review mode's panel reserves its height the same way, and the drawer reclaims its own when review mode closes.
- **The overview's structural tools exist only in review mode.** The eye, the X, drag and drop and the `h` / `del` / `shift+←→` keys appear while review mode (`e`) is on and go away when it's off, so an edit can't be made from what looks like navigation and then surface at a rebuild. Hidden and deleted slides still show their pending state, and the Rebuild deck button stays, since it's useful after the source changed by other means.
- **One convention for the keys the deck shows:** plain keys lowercase as pressed (`e`, `n`, `o`), modifiers spelled out (`shift+b`, `shift+←→`), in the pill's legend, the button titles, the review bar and its confirm bars.
- **Overview thumbnails no longer sit half a slide too low.** Reveal sets each live slide's inline `top` when it lays it out, and a slide it hasn't shown yet (beyond its view distance, `display: none`) keeps a stale value of half the slide height, which the thumbnail copy inherited. Copies are now re-centred from their own measured height whenever they're scaled, in the overview and in the presenter's sidebars.

### knowledgeware 1.12.0

- **slideware HTML decks have a review mode for text and speaker notes.** A deck built with `review: true` next to `slides` (or `node build-deck.js . --review`) inlines a second plugin, `review.js`: `E` makes every text field editable in place (plain text for the escaped fields, light HTML for columns, card bodies and bullets, cleaned on save) and opens a panel with the slide's notes and a comment box for whoever edits the deck next. Edits are kept per browser and per build until saved, then written as `edits.json` next to the deck (through the local server, the browser's save dialog, or a download), or copied as JSON to paste to Claude. Decks built without the flag carry none of the code.
- **The overview hides, deletes and reorders slides.** In a review deck, `O` shows every slide as built, hidden ones under a mask in the panel's own background so it reads in light and dark styles alike. An eye on each thumbnail hides or shows the slide in the lane being viewed, an X deletes it (struck through, with Undo), thumbnails drag and drop into a new order, and `H`, `Delete` and `Shift+arrows` do the same on the focused thumbnail. A Rebuild deck button beside Close turns solid green while anything is queued. The deck itself changes at the rebuild.
- **Every build folds `edits.json` into `slides.js` first.** The builder finds each edited text as a string literal in `slides.js` (or in the lane's overlay, for edits made in a lane) and rewrites it in the same quote style, leaving comments and layout alone. The overview's edits fold into the slide list itself: slide objects reordered, deleted ones removed, `hidden` set or cleared, each slide's comments travelling with it, and the file re-read to prove the result; in a lane, hidden and deleted become `hidden` in that lane's overlay and the order goes to the base deck. What can't be placed (the same text on two slides, text already changed, a slide list that changed since the edits) and every comment stay in the file, are layered over that build and printed with their reasons, and the file is deleted when nothing is left. Three ways to get there: ask Claude to "apply my edits" or "rebuild the deck", any rebuild at all, or `Shift+B` in the deck.
- **`serve-deck.js` serves a deck for the browser loop.** `node $PLUGIN/skills/slideware/html/scripts/serve-deck.js [dir] [--port 8010]` serves the deck on `127.0.0.1` only, saves posted edits and runs the build on request, so `Shift+B` in the deck saves, rebuilds (keeping review mode) and reloads on the same slide.
- **Every rendered text field is addressable.** The builder marks fields with `data-f` (`title`, `cards.1.body`, `notes`), light-HTML fields with `data-html`, and each section with `data-key` (the slide's `key`, else `s<n>` by position, then also `data-key-auto`) on every deck, review or not.
- **Lanes have colours.** Each lane takes a colour (an overlay's `color`, else one of six in turn); the overview's lane switcher shows a swatch in the current lane's colour, and in a deck with lanes every thumbnail carries a bar along its base, ink for a slide as the base deck has it and the lane's colour for one the lane changes (the builder marks those `data-lane-changed`). Two pop-ups refuse what can't be done: a deck whose slides carry no keys is asked to be rebuilt first, and hiding or deleting a slide from a lane is refused when the slide has no `key` of its own in `slides.js`.
- **The navigation pill sits above the notes drawer** (`N`), which used to cover it, and the drawer keeps its last lines clear of the pill. The pill gains an `i` whose tooltip lists every key: hover or focus shows it, a click pins it, Esc or a click elsewhere unpins; a review deck's list includes `E` and `Shift+B`.
- After a reorder, leftover edits and comments follow their slides to the new positional keys, so the next build can't wedge on stale ones; an order that doesn't list every slide exactly once is kept and reported instead of deleting slides; a deck dir given through a symlink builds from the folded `slides.js` (modules are re-read by resolved path); the fold's self-check no longer trips on "key:" inside a slide's text. In the overview, structural edits keep focus on the slide (the stylesheet constant shadowed `CSS.escape`), and a light-HTML field is cleaned on blur rather than on every keystroke, so Enter keeps its line break and the caret stays put. Found by a three-reviewer pass on the branch.
- A new test, `tests/deck-review-test.js`, builds a temporary deck against a stub reveal.js and js-yaml and covers the markup, the inlining, the fold's cases and the server; `validate-all.sh` and CI run it.

### knowledgeware 1.11.0

- **slideware HTML decks take a running footer.** A deck-level `footer` in `slides.js` (a string, or an array shown dot-separated) puts a footer on every slide but the title slide: the text on the left, the brand's logo and the page number (visible slides only) on the right, in the mono caption treatment. Reveal's own slide number turns off and the builder reserves the bottom band (`padding-bottom: max(var(--margin), 40px)`), so nothing but the footer sits in the bottom 40px. - **A navigation pill replaces Reveal's arrows.** A floating bar at the bottom of the deck (previous, the slide number, next, the current section's name, the overview, fullscreen) appears for 2.5 s after the mouse moves or on hover, and is hidden in print, in the presenter window and under the overview. It is drawn from the deck's tokens, so a dark style gives a dark pill. The builder sets `controls: false`.

- The format guide gains the fit rule for footered decks and a way to measure every slide against the footer at once (`?print-pdf` in an iframe). Proposed from the Enterprise Enablement decks, where a fork of the builder carried these first.

### adv 0.4.0

- **Codex's review mode.** For a review of local changes (the working tree, `--since`, `--commits`, or the last commit), the quality and testing reviewers now run `codex review`, Codex CLI's review-tuned mode, which may run the code to confirm a finding, instead of `codex exec` with the diff pasted into the prompt. Codex reads the changes from the repository itself: adv's prompt names the git scope, because in Codex CLI 0.163 `codex review`'s own `--uncommitted`, `--base` and `--commit` flags can't be combined with a custom prompt, and without the prompt both Codex reviewers would run the same generic review. A new `codex-review-adapter.py` rewrites the `[P1] title — /abs/path:lines` comments into adv's finding blocks for cross-examination, with paths made relative and priorities P0 to P2 mapped to 🔴 Bug and P3 to 🟡 Nit (the original priority stays in the finding). `--full`, `--pr` and the cross-examination rounds keep `codex exec`. A Codex reviewer that falls back to Claude gets the diff prompt as before.
- **Models and tokens in the report.** Every engine is now asked for JSON (`codex exec --json`, `gemini -o json`, `claude --output-format json`), which is where the model that answered and the token counts live, so the status line gains `model_used`, `tokens_in` and `tokens_out`, `run-phase.sh` reports them per reviewer and per round with phase totals, and the review's summary, metadata and `findings-<timestamp>.json` name the models and the token totals. Config warnings and errors that the JSON carries go to `dispatch.log`, and output that isn't JSON is kept as the response as is. The health check, the REST quota probe and the stderr classification are unchanged, since Gemini CLI never reaches its JSON error path on a 429.
- **`--pr <number|url>`.** Reviews a pull request on the repository's GitHub remote: preflight reads the diff with `gh pr diff` and the metadata with `gh pr view`, nothing is checked out, and the report names the pull request. The reviewers work from the diff alone, so Codex's review mode is off for this scope; the README gives the `gh pr checkout` plus `--since <base>` route for a review that reads the pull request's files. Without `gh`, preflight says so and names that route.
- **Fixed:** `run-phase.sh` printed every dispatch's status line on its stdout ahead of its own summary; the status lines now go to `status-<reviewer>.json` files in the temp folder, so the orchestrator reads one JSON line.
- **Fixed:** `run-phase.sh` counted a reviewer whose dispatch never wrote an output file as a success, so a crash before the engine call (on stock macOS bash 3.2, the empty model-argument array itself was one: `model_args[@]: unbound variable`) silently lost that reviewer and skipped the Claude fallback. A missing output file is now a failure that goes through the fallback chain, and the expansion works on bash 3.2.
- **Fixed:** a cross-examination round in which an engine's reply had no `New Finding` (or no `VALIDATE`, `DISPUTE` or `AMEND`) crashed `run-phase.sh` while counting verdicts, because `grep -c` prints `0` and the `|| echo 0` after it added a second `0` to the arithmetic. The orchestrator then saw no summary for the round. Zero counts now work.
- **Fixed:** with a healthy Gemini, every Gemini call in 0.3.0 ran `gemini -m engine_default`. Preflight reported `engine_default` as the model when the CLI should pick its own, and the orchestrator passed that string on as a real model, so each reviewer failed with `model_not_found` and ran on the quota fallback model (`gemini-3-flash-preview`) instead of Gemini's auto mode, without saying so. Preflight now reports an empty model, and `run-phase.sh` ignores the placeholder. The review of this branch (adv's own smoke test, 2026-10-23) found this.
- **Fixed:** the Gemini REST probe reported `000000` on a network failure, because curl prints `000` and the script added another `000`, so a connection problem failed the health check instead of letting the CLI try. Under 1Password, a curl failure was also mistaken for a vault problem (`auth`).
- **Fixed:** a working tree whose only changes are new untracked files fell through to the last-commit scope, because the smart default looked only at `git diff --stat`. Untracked files now make a working scope, and their content goes into the diff as added files, not only their names.
- `--pr` checks for `gh` before the engine health checks. `--check-deps` reports `gh`. The reviewer prompts explain the three scope forms (a diff, a file manifest, or an instruction naming a git scope). `tests/dispatch-test.sh` now covers `run-phase.sh` and `preflight.sh` too, with fakes that answer in each CLI's JSON shape: model and token reporting, Gemini's JSON error, Codex review mode end to end, the Gemini fallback chain, and `--pr`.

### adv 0.3.0

Tested against Codex CLI 0.163.0 and Gemini CLI 0.65.0 (October 2026). Both CLIs changed enough since adv 0.2.0 that every engine call had been failing.

- **Fixed:** Codex calls failed on `--full-auto`, which Codex CLI 0.163 removed; the read-only sandbox doesn't need approvals, so the flag is gone. Gemini calls failed on the trusted-folder check that Gemini CLI 0.65 applies to headless runs; adv now passes `--skip-trust`. Gemini's `--sandbox` is no longer passed either, because in 0.65 on macOS it broke the CLI's API calls and every call spent 70 seconds retrying; `--approval-mode plan` keeps Gemini read-only.
- **Fixed:** adv no longer names models. `gemini-2.5-pro` (the default) and `gemini-2.0-flash` (the quota fallback) were both retired in 2026 and returned 404. Each CLI now uses its own current default (`gpt-6.1-sol` and Gemini's auto mode at the time of testing); `ADV_CODEX_MODEL`, `ADV_GEMINI_MODEL`, `ADV_CLAUDE_MODEL` and `ADV_GEMINI_FALLBACK_MODEL` (default `gemini-3-flash-preview`) override them. A model that doesn't exist or isn't on your plan is reported as `model_not_found` (exit 6) and triggers the same fallback as a quota failure.
- **Fixed:** a failed engine call crashed `dispatch.sh` before it wrote its error marker, because the marker used `ERROR_TYPE` before the script set it. `run-phase.sh` then counted that reviewer as successful, so the Gemini quota retry and the Claude fallback never ran, and the review lost that reviewer's findings.
- **Fixed:** engine calls stop after 300 seconds on macOS too. The limit used to depend on GNU `timeout`, which macOS doesn't ship, so a stuck Codex or Gemini call could hang the review. Without `timeout` or `gtimeout`, a python3 watchdog now stops the engine and every process it started, and the call fails with `error_type: timeout`. Gemini calls made through 1Password's `op run` get the same limit, and `--check-deps` now checks for python3.
- **Fixed:** each engine call logs to its own file before it's folded into `dispatch.log`, so parallel reviewers can't have another engine's error attributed to them. The 1Password path no longer needs bash 4.4 (stock macOS has 3.2), and an `op` failure to supply the key is reported as `auth`.
- The Gemini health check first sends one request through the REST API, because Gemini CLI answers an exhausted quota by retrying and switching models in silence, which looked like a hung engine. The probe reports quota (429), a bad key or a missing model in about a second, and the review falls back to Claude at once instead of after a 300-second timeout per call.
- `--check-deps` prints each CLI's version, notes when one is older than the tested version, and reports `BROKEN` when a CLI is on `PATH` but can't run. The health check allows 60 seconds instead of 30, since Gemini's first run of a session took about 40.
- `plugins/adv/tests/dispatch-test.sh` runs `dispatch.sh` against fake engines (success, auth, quota, hang, model not found) on any bash; `validate-all.sh` and CI run it.
