# Contributing to SWE Marketplace

Thanks for considering a contribution. This marketplace stays small and curated, so the bar for new plugins is "I'm actually using this" — but agent improvements, doc fixes, and bug reports are always welcome.

## Ways to contribute

- **Improve an existing agent or skill** — tighter prompts, better examples, fixed metadata.
- **Add a new plugin** — see [Adding a new plugin](#adding-a-new-plugin) below.
- **Report a bug** — open an issue with `claude --version`, the plugin name, and reproduction steps.
- **Fix the docs** — typos, broken links, unclear instructions.

If you're proposing something larger (new plugin, restructure), open an issue first so we can sock the design before you spend time on a PR.

## Development setup

Requirements:

- Python 3.10+ (only stdlib used by the generator)
- `claude` CLI on `PATH` for local validation ([install instructions](https://docs.claude.com/en/docs/claude-code/setup))
- `git` and a fork of this repo

```bash
git clone git@github.com:<you>/swe-marketplace.git
cd swe-marketplace
./scripts/validate-all.sh   # confirm a clean baseline before changing anything
```

## The golden rule: edit `marketplace.json`, not `plugin.json`

The repo ships two manifest layers:

- `.claude-plugin/marketplace.json` — **source of truth**. Every plugin's metadata lives here.
- `plugins/<name>/.claude-plugin/plugin.json` — **generated** from the matching marketplace entry.

You only edit `marketplace.json`. The per-plugin `plugin.json` is regenerated by a script and CI fails any PR where the two have drifted.

### Workflow

```bash
# 1. Edit your plugin's entry in marketplace.json
$EDITOR .claude-plugin/marketplace.json

# 2. Regenerate the per-plugin manifest(s)
python scripts/synthesize-plugin-manifests.py

# 3. Validate everything with the Claude CLI
./scripts/validate-all.sh

# 4. Commit both files together
git add .claude-plugin/marketplace.json plugins/<name>/.claude-plugin/plugin.json
git commit -m "feat(<plugin>): <what changed>"
```

### Field rules (enforced by the generator)

`plugin.json` is the matching `marketplace.json` entry **minus** `source`, `category`, and `strict` — those are marketplace-only.

Required formats (per `claude plugin validate`):

| Field | Format |
|---|---|
| `agents` | File paths — `["./agents/foo.md"]`, *not* parent dirs |
| `skills` | Subdir paths — `["./skills/coordinator"]` |
| `commands` / `hooks` | File paths |
| `repository` | String URL, not `{type, url}` |
| `author` | Object `{name, email?, url?}`, not bare string |
| `dependencies` | Array of plugin names, not version-pinned object map |

Every agent file needs YAML frontmatter or the validator emits a warning.

## Adding a new plugin

1. **Create the directory structure** under `plugins/<your-plugin>/`:
   ```
   plugins/<your-plugin>/
     agents/         # YAML-frontmatter markdown files
     skills/         # one subdir per skill, each with an agent.md
     commands/       # markdown files (optional)
     hooks/          # shell scripts (optional)
     README.md       # quick overview for the plugin
   ```

2. **Add an entry to `.claude-plugin/marketplace.json`** under `plugins[]` with at minimum `name`, `version`, `description`, `author`, `repository`, `license`, and the component arrays.

3. **Generate and validate**:
   ```bash
   python scripts/synthesize-plugin-manifests.py
   ./scripts/validate-all.sh
   ```

4. **Open a PR** referencing any related issue. Include a sentence on what gap the plugin fills and which agents/skills/commands it adds.

## Pull request checklist

- [ ] `marketplace.json` updated (if you touched anything in `plugins/`)
- [ ] `python scripts/synthesize-plugin-manifests.py --check` passes (no drift)
- [ ] `./scripts/validate-all.sh` passes (zero errors, zero warnings)
- [ ] Every new agent file has YAML frontmatter
- [ ] Commit message follows the existing style (Conventional Commits with optional gitmoji prefix; see `git log` for examples)
- [ ] Doc updates included where behavior changed

## Commit message style

Loose Conventional Commits. Examples from history:

```
feat: ship per-plugin plugin.json manifests for SDK runtime loaders
fix(research-team): relocate output paths to ~/Documents/Claude/Research
docs: add CLAUDE.md with dual-manifest workflow guidance
```

Scope is the plugin name when the change is plugin-specific.

## Reporting bugs

Open an issue using the bug template. Useful details:

- `claude --version` output
- Plugin name and version (from `marketplace.json`)
- What you ran, what you expected, what happened
- Whether you restarted Claude Code after install

## Questions?

Open a discussion (once enabled), file an issue, or reach out via the contact info in the [README](./README.md). Thanks for helping keep the marketplace useful.
