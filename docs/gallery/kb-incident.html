INC-2419: API gateway 502s in eu-west, 39 minutes

Severity 2GatewayActions open: 2

On 2026-10-14 between 09:12 and 09:51 UTC, 38% of API requests in eu-west returned 502. A config change to the gateway's upstream timeout triggered it; a health check that didn't exercise the new code path let it spread, and a 25-minute manual approval delayed the rollback. No data was lost. 2,140 customers saw errors.

Why it spread

The timeout change was correct for 95% of routes. The two routes that stream large responses need more than 5 seconds, and the health check hits /healthz, which returns in 3 ms. So the canary looked green at 1%, 10% and 50%, and the deploy went to 100% in four minutes.

Contributing factor The approval policy requires two approvers for any gateway change, including a rollback to the previous version. That rule cost 22 of the 39 minutes.
What worked Per-route alerting named the two routes within two minutes. Without it the on-call would have seen a service-wide error rate and no pointer.
